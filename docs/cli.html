Commands

Command reference

Everything in the GUI is also a command. avrig COMMAND --help lists every option; global options are --config FILE, --sim (simulated cameras, no hardware), -v and -q.

Commands that use the cameras take an instance lock, so they refuse to run while the GUI or another recorder holds the rig. After-the-drive commands refuse to start while a recording is running.

Rig and recording

CommandPurpose
statusHealth of cameras, sensors and clocks without streaming
check [-t S]Stream everything for a few seconds: sync, drops, sensors, quality, host and health (exit code = health)
monitor [--remote]Live terminal dashboard
sync on|off|status [--boot]Hardware frame sync. on warm-starts the cameras, enables sync, reads it back and verifies the lock; --boot waits for the cameras and retries once (used by the boot service)
record [-t S] [--operator --vehicle --route --weather --light …]Preflight-gated recording with metadata; stdin markers (Enter, a digit, or text)
gui [--remote]The operator application (optionally with the LAN status page)
soak 2hLong recording + verify + report, with a thermal / load / sync trend
autoHands-free collection: record while driving, stop when parked (normally the avrig-auto service)
perf on|off|statusCollection mode (clocks, paused containers, stopped services while recording)
wizardCamera-position verification: cover and uncover one lens at a time; writes udev rules for stable /dev/cam_<position> names

Sensors and clocks

CommandPurpose
clock [--calibrate]Master-clock state; measures the GNSS message latency
gnss [--raw-enable] [--rf-enable] [--ntrip] [--enable] [--persist]Receiver: raw measurements for PPK, interference reports, an RTK caster test, time marks of the camera trigger
imu [--set FUNCTION LINE --yes]Xsens SyncIn settings (show, or write and read back)
can [-t S]CAN interface state and frame rate
mount [status|reset|check SESSION]Camera-mount guard: references, forget one (--cams X --yes), check a recorded drive (--adopt stores learned references)
ledsync --gpio LINE / --analyze SESSIONOptical sync check with an LED

Sessions: QA, storage, export

CommandPurpose
sessionsIndex: duration, size, status, verify result, offloaded, markers
verify SESSION… [--quick] [--report] [--json]Offline QA; writes verify.json
report SESSIONSelf-contained report.html
trends [--html]Rig health across sessions, with wear findings
events SESSION… [--list] [--write]Re-detect automatic events with the current thresholds
offload SESSION… --dest DIRSHA-256-verified, resumable copy with receipts
prune --older-than DAYS [--yes]Delete only sessions whose verified copy still re-hashes correctly (dry run by default)
depotVerify + offload (+ prune) when the destination is reachable (normally a timer)
retain SESSION [--pre --post] [--replace --yes]Event-only copy (hard links), verified before anything is deleted
export mcap SESSIONIndexed MCAP for Foxglove / ROS 2 (video copied verbatim)
export frames SESSION --markers|--every S|--at NSTimestamp-matched frame sets from all cameras
fleet --rigs name=URL,…One dashboard for several rigs' status pages

Calibration and trajectory

CommandPurpose

calibrate boardPrintable ChArUco board at true size
calibrate solve SESSION --square M [--register NAME --activate]Intrinsics + extrinsics from a board recording
calibrate kalibr SESSIONExport for camera-IMU calibration in Kalibr
trajectory SESSION… [--visual] [--vo-cam CAM]Smoothed 6-DoF trajectory (GNSS + IMU, optional CAN and visual speed)

Root setup script

sudo bash setup/avrig-install.sh --autostart
sudo bash setup/avrig-install.sh --collection-mode --pause-containers "NAME" --stop-services "NAME"
sudo bash setup/avrig-install.sh --can --bitrate 500000 --ifaces "can0 can1"
sudo bash setup/avrig-install.sh --auto
sudo bash setup/avrig-install.sh --depot
sudo bash setup/avrig-install.sh --uninstall
bash setup/install-desktop.sh [--remove]      # desktop shortcut, no root

Environment

AVRIG_PROGRESS=1
Print progress lines even when stdout is not a terminal (the GUI sets it to drive its progress bars).
~/.config/avrig.yaml
Configuration; validated, unknown keys rejected.
~/.config/avrig/presets.yaml
Pick lists for operators, vehicles, routes, conditions and tags.
~/.local/share/avrig/
Models, calibration registry, mount references, catalog and map databases.
~/.local/state/avrig/
Audit log and application log.
