Engineering notes

What it took

Most of the work on this rig was not writing features; it was finding out why something that looked fine was not. These are the problems the team hit, how each was found, and what changed. Several of them produce no error message at all.

Bringing up the hardware

The vendor installer did not finish
The camera driver installer failed in two places on this L4T release (a device-tree tool looking for DTBs in the wrong folder, and an abort part-way through). Both steps were completed by small repair scripts kept with the rig. The module autoload list also had to drop two modules that do not exist on Orin, because listing them fails the module-load service.
A system update silently removed every camera
An L4T package update overwrote the DTB the camera overlay was merged into, and replaced the vendor's patched camera modules. Fix: merge the overlay into a separately named DTB that no package owns, and a script that reinstalls and checks the modules.
V4L2 lies about the format
Asking for 2048 wide returns success and 1920. Every format is now read back and compared, not trusted.
Node numbers move
/dev/videoN follows probe order; a webcam or one failed probe renumbers everything, and the bus path is shared by two nodes. Cameras are identified by the sensor's I²C bus and address in the device name, and physical positions are confirmed one lens at a time with avrig wizard.
The deserializer board failed
Both deserializers progressively stopped answering on their camera I²C buses over several days — a hardware fault that looked like a software regression. Reading the persistent kernel log across boots bounded when it started; the board was serviced.
GNSS jammed by a USB 3 hub
Zero satellites with the antenna “OK”. The receiver's RF report showed a pinned-low AGC and a jamming indicator of 190/255: USB 3 SuperSpeed noise on the L1 band. Moving the receiver off the hub fixed it — and is why Argus Labs now watches the receiver's RF report live.
The PPS line never fired
The GNSS timepulse is configured and the host GPIO interrupt is armed, but no edge has ever arrived (wiring or pin-mux). Meanwhile /dev/pps0 is the kernel's synthetic test source: binding to it would have produced perfect, fictitious sync. Absolute time comes from NTP until the GNSS clock is installed with a fix.

Timestamps that told the truth

The single most important finding. Early capture tools used GStreamer's v4l2src and recorded “driver timestamps”. They did not: because the Tegra's TSC counts from power-on, v4l2src judged the stamps implausible and silently replaced them with dequeue time. On a quiet machine that looked fine (58 µs median spread); under load the same hardware read 0.3–0.6 ms median and 3.5–5 ms p95.

Reading the driver timestamps directly from six concurrent captures showed the truth: ~15 µs per-frame jitter and a 30 µs median spread. The capture core was rewritten to dequeue V4L2 buffers itself and hand GStreamer only the encoding, with the true capture time as PTS. Every sync number in this documentation comes from driver timestamps.

Hardware frame sync

  1. First attempt: the streams stalled. The trigger switch was on external with nothing wired, so the sensors waited for edges that never came. Back on internal, the trigger worked.
  2. Then: drops. On the original deserializer board the trigger missed edges — ~8 dropped frames per minute, always two-frame jumps clustered per deserializer, which pointed at the trigger, not the encoder or disk. After the board was serviced: 0 drops in 2 minutes.
  3. Then: the cold-boot failure. A boot service that set sync before anything had streamed left four of six cameras with no frames and a restart storm. The control experiment — same boot, sync off — was clean. The successful measurements had all been taken on a warm rig, and a one-camera smoke test does not reproduce the failure.
  4. The fix: warm start, verify, fail visibly. Stream all six free-running first, then set sync, read it back and verify the lock; at boot, retry once and otherwise leave the rig free-running with preflight blocking recording. A camera left dead is worse than an unsynced rig that says so.

Principles that came out of it

  • Measure the thing, not a proxy. Arrival time is not capture time; a written control is not a set control; a smoke test with one camera is not six cameras at boot.
  • Every live feature is A/B-tested on the rig with the recorder's own CPU time and the drop count, before it is on by default.
  • Side work can lose data, the recording cannot. Leaky branches, bounded queues, rate limits before expensive conversions, callbacks that cannot raise.
  • Fail visibly. Free-running is allowed, silent free-running is not. A forced recording is marked forced.
  • Offline means offline. Heavy work refuses to run during a recording and stops if one starts.
